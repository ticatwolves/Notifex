# ADR-010 — Schema migrations and tenant-scope enforcement

- **Status:** Accepted (2026-11-27)
- **Decider:** Shobhit (approved as part of the Phase 0 plan)

## Context
CLAUDE.md requires reviewed migration files for every schema change, tenant scoping in the store layer, and a test proving isolation for every store method. ent alone gives code generation and auto-migration. Auto-migration is not acceptable in production, and ent edges can't express composite tenant-consistent foreign keys.

## Decision

### Migrations
- **ent schemas (`ent/schema`) are the source of truth for tables, columns and indexes.** Foreign keys are declared in `ent/schema/constraints.go`, not as ent edges.
- **Versioned SQL migrations are generated** by `ent/migrate/main.go` (`make migration name=…`). It replays `migrations/` into a throwaway Postgres (testcontainers), then diffs against the ent schema plus the declared foreign keys, using ent's Atlas integration as a library. Output is golang-migrate `.up.sql`/`.down.sql` files plus `atlas.sum`. Drop-column changes are never generated; destructive steps are written by hand as expand/contract.
- **Migrations are applied by `cmd/migrate up`** (golang-migrate with an advisory lock, migrations embedded in the binary). It runs as a one-off ECS task before each deploy and as a one-shot compose service locally. Forward-only: there is no `down` command. A dirty database is reported and never auto-fixed.
- **CI** checks that generated ent code is current, that `migrate-check` finds no un-migrated schema changes, and runs **squawk** against the SQL for unsafe operations (non-concurrent index builds, NOT NULL without a default, and so on). Integration tests run the real migration files, never ent auto-migrate.

### Tenant scoping (defense in depth)
1. **Store methods take `TenantID` explicitly** and add an explicit `tenant_id` predicate.
2. **`TenantMixin`** on every tenant-owned table installs an ent interceptor and a mutation hook. Queries, updates and deletes get `tenant_id = <scope>` added. Creates must carry the scope's tenant id, or have it filled in. **With no scope, every operation fails (`tenantscope.ErrMissing`) in every environment.** Bypasses are explicit, named and greppable: `ReasonAPIKeyLookup`, `ReasonUserMemberships`, `ReasonPlatform`.
3. **Composite foreign keys** (`(tenant_id, application_id)`, `(tenant_id, application_id, environment_id)`) make cross-tenant references impossible at the database level, even for raw SQL. `tenant_id` is denormalized onto `environments` and `api_keys` for this.
4. Postgres row-level security remains the planned fourth layer (Phase 8).

### Errors
A foreign-key violation on create maps to `ErrNotFound`, so another tenant's ids are indistinguishable from unknown ones. A restrict violation on delete maps to `ErrConflict`. Postgres error strings exclude DETAIL, so key values such as emails never appear in errors.

## Consequences
- Adding a table means: an ent schema, `TenantMixin` if it is tenant-owned, its foreign keys in `constraints.go`, `make migration`, a row in `TestTenantIsolation`, and store CRUD tests against real Postgres.
- Mutation-tested: disabling the interceptor's filter fails `TestScopeEnforcementFailsClosed`.
- The ent `intercept` feature is required. The schema package imports `ent/intercept`, so a fresh checkout's first `go generate` needs the generated package to exist. It is committed, so this only matters if `ent/` is wiped.
- The tenant id is generated by the caller (`store.NewTenantID()`) because the DEK's encryption context binds the DEK to it (ADR-006).

## Alternatives considered
- **ent auto-migrate in production.** Not reviewable, and can't do expand/contract. Rejected.
- **The Atlas CLI with `ent://` for diff and lint.** It needs the CLI binary and a Go toolchain wherever it runs. The library route needs neither. squawk covers lint.
- **Hand-written composite foreign keys in a SQL migration.** The next generated diff would see them as drift and drop them. Rejected in favor of adding them to the desired schema in the generator.
- **Logging instead of failing on a missing scope in production.** It fails open at exactly the moment it matters. Rejected.
